# Porting differences

The upstream submodule is unchanged. All exceptions below live in maintained compatibility code or deterministic generated output.

1. **Web vertex fields.** `tools/shader-build/generate-web-appdata.ts` copies upstream `lil_common_appdata.hlsl` into a generated build artifact and injects Three-compatible `skinIndex` and `skinWeight` fields. `skinIndex` is a float attribute because Three supplies integer component buffers through its normal float attribute path; the compatibility function converts it to `uint4` before bone lookup.
2. **Scene-light mutation.** Upstream `LIL_FORCE_SCENE_LIGHT` can assign material globals, which Vulkan uniform blocks forbid. Wrappers replace that macro with a no-op and the private renderer context applies the equivalent force-scene-light values before upload.
3. **Matrix convention.** Cross-compiled GLSL retains HLSL row-vector expressions. Runtime object, camera, bind, light-shadow matrices are transposed during upload. This is an ABI rule, not a vendor edit.
4. **WebGL varying names.** SPIRV-Cross names separate stage interfaces `out_var_*` and `in_var_*`. ESSL 3.00 links varyings by name, so the generator deterministically renames fragment inputs to their vertex output names. A compiler test verifies every pair.
5. **GLSL version placement.** Standalone generated files keep `#version 300 es` for glslang. Three prepends material defines, so `LilToonMaterial` removes that first directive and sets `glslVersion = GLSL3`, allowing Three to place it first.
6. **Shadow ABI.** Unity shadow macros are replaced by one Three directional-light matrix and RGBA-packed shadow texture with 2×2 PCF. Three's depth bias and receiver normal bias are applied; cascades, VSM, and shadow radius/intensity parity are not reproduced.
7. **Lighting ABI.** Unity/URP/HDRP lighting is represented by the first visible Three `DirectionalLight`, additive Three `AmbientLight` values, and Unity-compatible SH coefficients for visible `HemisphereLight` objects. Two adjacent, co-directed HemisphereLights form one Trilight profile: first sky, midpoint(first ground, second sky), then second ground; pair intensity is the sum of both light intensities. A lone hemisphere uses its own sky and ground with their midpoint as equator. Uneven Trilight profiles currently require the shared light direction to be world Y because the Unity SH quadratic basis is world aligned; other orientations throw instead of silently changing the field. For each linear RGB channel, Unity 2022.3.22f1's runtime `RenderSettings.ambientProbe` measurements match `c0=(S+4E+G)/6`, `c1=(sqrt(6)/9)*(S-G)`, `c6=(5/192)*(2E-S-G)`, and `c8=3*c6`; other coefficients are zero. Unity's native conversion is not published in UnityCsReference, so this formula is grounded in recorded probe coefficients for Flat plus three unequal/chromatic Trilight profiles, not attributed to public implementation source. The lilToon evaluation being matched is `lil_common_functions.hlsl:lilShadeSH9` (pinned lilToon source lines 849-868) and its toon diffuse use in `lilGetSHToon` (lines 911-928). Coefficients use Unity `PackCoefficients` layout (Unity FPSSample `SphericalHarmonics.cs`, lines 40-55). Do not add a fixed ambient baseline: it made the corrected Unity Flat fixture render center pixel 60 versus three-liltoon's 67; `_LightMinLimit` is a separate material clamp. Additional lights, lightmaps, probes, and Unity attenuation modes are unsupported and remain reported by the owning higher-level integration.
8. **Environment ABI.** A public `THREE.CubeTexture` is sampled directly. The material extension can embed decoded linear half-float faces and authored mips; large cubes retain their full storage cost. The adapter does not access private PMREM/equirect renderer state and therefore cannot reproduce Unity reflection-probe blending.
9. **Texture safety.** Unassigned material texture reads become neutral constants (including upstream alpha-zero shadow-color fallback); active system samplers retain safe fallback bindings. Incompatible 2D/cube textures are ignored to avoid a WebGL `INVALID_OPERATION`; active mismatches are available through `getWarnings()` and loader warning callbacks.
10. **Deformation.** Bone matrices use Three's public bone texture and bind matrices. Position/normal morphs reuse Three's renderer-owned displacement texture and installed shader equations before the compiled lilToon vertex entry. A material-owned R32F texture carries all mesh weights, avoiding a growing vertex-uniform array without changing the public morph API. There is no package-defined morph cap or CPU overflow; device texture/resource limits and morph-geometry lifecycle rules apply. See [Three.js morph integration](ARCHITECTURE.md#threejs-morph-integration).
11. **Pass architecture.** Outlines are a package-owned child draw and shadow casting uses Three depth/distance materials. Basic Refraction/Gem use framebuffer scene-color capture and Gem adds a black prepass. WebGL2 multisampled targets use a public-context color resolve with restored framebuffer bindings. Fur lowers upstream geometry-stage ribbon interpolation to vertex invocations over generated topology; animated source vertices use a float render-target GPU preparation pass with four-weight skinning, shared by both fur draws. Source morphs are cached on the CPU; devices without EXT_color_buffer_float retain cached CPU skinning. Fur collision/light interaction and fur shadow geometry remain unsupported. Refraction Blur retains horizontal blur, second capture and vertical blur/refraction. Fur Cutout and Two-pass retain alpha/prepass behavior. Transparent Normal/OnePass/TwoPass preserve per-group pass order and state, with implicit Three double-sided splitting disabled. Transparent outlines follow the surface. Additional lights and Unity shadow parity remain deferred. Unsupported families still warn and use ordinary forward fallback. The former pass-constructor exports are deprecated material conveniences; use `LilToonMaterial({renderMode})`.
12. **Unsupported platform facilities.** Instancing, stereo/WebXR, VRC Light Volumes, AudioLink, tessellation, arbitrary Unity GrabPass configurations, and pipeline-specific editor facilities are not emulated. The supported refraction/gem captures are described above.
13. **Material specialization.** A generated copy of `lil_common.hlsl` adds specialization guards after input declarations; the vendor checkout remains untouched. Runtime GLSL specialization removes unassigned/dormant texture reads, preserving neutral defaults and upstream render-mode behavior. Explicit resource reflection supplies sampler ownership, and equivalent bindings may alias while retaining independent UV transforms. Actual context limits are checked per stage and combined, with no fixed sixteen-total policy or feature-priority fallback. See [Material specialization](MATERIAL_SPECIALIZATION.md).

`shader/patches/` contains no vendor patches. Current adaptations are implemented by wrappers, compatibility definitions and generated transforms. See [architecture](ARCHITECTURE.md) for the source layout.
